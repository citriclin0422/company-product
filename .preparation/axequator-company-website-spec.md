# 立赫精密公司產品網站建置規格

## 1. 專案概述

- 公司中文名稱：立赫精密
- 英文名稱：AXEQUATOR PRECISION LTD
- GitHub Repository：`citriclin0422/company-product`
- 預計公開網址：`https://citriclin0422.github.io/company-product/`
- 網站類型：B2B 半導體設備服務公司單頁式形象網站
- 主要語言：繁體中文；重要標題及服務名稱提供英文輔助
- 主要目標：建立專業可信賴的公司形象，讓半導體廠設備、廠務、採購及工程承辦人能快速理解服務內容並提出洽詢

## 2. 業務定位

立赫精密服務半導體相關企業，主要業務包括：

1. 半導體設備維修與保養支援。
2. 設備耗材及零組件檢查與更換。
3. 鋼瓶更換及相關現場作業支援。
4. 依客戶廠區規範執行現場工程服務。

網站不得自行宣稱未經確認的服務，例如原廠授權、24 小時服務、特定安全認證、零事故紀錄、特殊氣體處理資格或特定品牌設備維修能力。

## 3. 目標受眾

- 半導體廠設備工程師與設備主管
- 廠務、氣體供應及環安衛相關人員
- 採購、供應商管理及工程發包窗口
- 尋找設備維修與零件更換合作廠商的企業客戶

## 4. 核心溝通主軸

- 專業：理解半導體廠區工作流程與設備服務需求。
- 安全：依客戶廠區規範、標準作業程序及工作許可制度執行。
- 精準：重視作業確認、零件核對、施工紀錄及完工回報。
- 協作：配合客戶設備、廠務、環安衛及承攬管理窗口。
- 穩定：以降低設備異常時間及維持生產運作為服務方向。

以上文字屬網站定位；正式上線前仍需由公司確認是否符合實際能力及合約用語。

## 5. 資訊架構

### 5.1 固定導覽列

- 左側：公司 Logo、立赫精密、AXEQUATOR PRECISION LTD
- 右側錨點：首頁、關於立赫、服務項目、作業流程、專業與安全、聯絡我們
- 行動版：漢堡選單
- 主要 CTA：`服務洽詢`

### 5.2 首頁主視覺 Hero

目的：第一個畫面直接說明服務對象與核心業務。

建議文案：

> 半導體設備維修與現場工程服務
>
> 提供設備維修、零組件更換與鋼瓶更換作業支援，配合客戶廠區規範，重視安全、品質與施工紀錄。

按鈕：

- `查看服務項目`：跳至服務區塊
- `聯絡我們`：跳至聯絡區塊

視覺建議：使用真實且已獲授權的設備維修、無塵室或工程人員照片。取得公司照片前，以低調的半導體製程線條、設備局部或抽象晶圓圖形作為臨時背景，不使用來源不明的客戶廠區照片。

### 5.3 關於立赫 About

內容結構：

- 公司定位：服務半導體產業的設備維修與工程支援團隊。
- 服務理念：安全優先、作業確實、溝通清楚、按規範執行。
- 合作方式：依工作需求確認範圍、時程、作業條件與交付紀錄。

待公司補充：成立年份、所在地、服務區域、團隊經驗、代表性實績及公司統編。

### 5.4 服務項目 Services

使用三張主要服務卡片：

#### A. 半導體設備維修

- 設備異常檢查與維修支援
- 預防保養及定期檢查支援
- 維修前後狀態確認與作業紀錄
- 實際可服務設備品牌與機型須由公司補充

#### B. 零組件檢查與更換

- 耗材與零組件狀況確認
- 拆裝、更換與復原支援
- 料號、數量與安裝位置核對
- 完工後功能確認與紀錄

#### C. 鋼瓶更換作業支援

- 作業前條件與工作許可確認
- 依客戶 SOP 進行更換及現場配合作業
- 作業區域、工具與人員狀態確認
- 完工交接及紀錄

注意：正式文案必須經公司環安衛或業務窗口確認，不描述未經證實的氣體種類、證照或處置能力。

### 5.5 作業流程 Process

以五步驟橫向時間軸呈現，行動版改為直向：

1. 需求確認：設備、零件、作業位置與期望時程。
2. 現場及風險確認：廠區規範、工作許可、PPE 與施工條件。
3. 維修／更換執行：依核准範圍及標準程序作業。
4. 功能及環境復原：確認設備狀態、工具、零件與作業區域。
5. 完工回報：提供作業結果、異常事項及後續建議。

### 5.6 專業與安全 Professional & Safety

以四個圖示資訊卡呈現：

- 作業前確認：工作內容、風險及人員分工。
- 規範化執行：遵循客戶 SOP、工作許可及廠區規定。
- 品質核對：零件、安裝位置及作業結果雙重確認。
- 紀錄與交接：保留必要施工紀錄並清楚回報。

不得放置 ISO、SEMI、職安或其他認證標章，除非公司提供有效證明及使用授權。

### 5.7 合作對象或服務場景

可列出不涉及客戶名稱的服務場景：

- 半導體製造廠
- 封裝與測試廠
- 廠務與氣體供應系統相關作業
- 設備商或工程承攬合作

未取得書面同意前，不展示客戶 Logo、廠區名稱或現場可識別資訊。

### 5.8 聯絡我們 Contact

第一版採靜態聯絡資訊與 Email 連結，避免假裝表單已送出。

欄位／資訊：

- 公司名稱
- 聯絡人或部門
- 電話
- Email
- 公司地址
- 服務區域
- 營業時間

可加入 `mailto:` 按鈕；若日後串接 Formspree、Google Forms 或後端 API，再啟用完整表單。表單需提供姓名、公司名稱、Email、電話、需求類型、需求說明及個資同意勾選。

### 5.9 頁尾 Footer

- 立赫精密｜AXEQUATOR PRECISION LTD
- 公司聯絡資訊
- GitHub Pages 網站版權文字
- 隱私權說明連結（啟用蒐集資料的聯絡表單時必須加入）
- `© 2026 AXEQUATOR PRECISION LTD. All rights reserved.`

## 6. 視覺設計方向

- 設計主題：精密工程 × 半導體工業 × 安全可信賴
- 主色：深海軍藍 `#0B1F33`
- 輔色：科技藍 `#1677B8`
- 強調色：安全橙 `#F59E0B`，只用於 CTA、流程節點及安全提示
- 背景：冷白 `#F5F8FA`
- 主要文字：`#15202B`
- 中文字體：`Noto Sans TC`，提供系統字體 fallback
- 英文字體：`Inter` 或 `Arial`
- 圖示：線性工程圖示，風格一致；不要使用 emoji 作為正式圖示
- 卡片：小圓角、細邊框、輕陰影；避免過度玻璃擬態
- 動效：淡入與小幅位移，並尊重 `prefers-reduced-motion`

## 7. 技術方案

### 7.1 第一版技術選擇

- Framework：Vite + React
- Language：JavaScript；團隊熟悉時可改 TypeScript
- Styling：Tailwind CSS 或集中式 CSS；不要同時混用多套 UI Framework
- Icons：Lucide React
- Hosting：GitHub Pages
- Repository：`citriclin0422/company-product`
- Build output：`dist/`
- Deployment：GitHub Actions 自動建置與發布

### 7.2 Vite 必要設定

`vite.config.js` 必須設定：

```javascript
export default defineConfig({
  plugins: [react()],
  base: '/company-product/',
})
```

未設定 `base` 會造成 GitHub Pages 上的 CSS、JavaScript 或圖片路徑錯誤。

### 7.4 功能需求

- 單頁錨點導覽與平滑捲動
- 固定導覽列及目前區段提示
- 手機版選單可使用鍵盤操作並正確關閉
- 所有圖片具備有意義的 `alt`
- CTA 能跳至服務或聯絡區塊
- Email 與電話連結使用 `mailto:`、`tel:`
- 不加入未實作的登入、後台、即時客服或表單成功訊息
- 保留未來新增中英文切換及服務詳情頁的擴充空間，但第一版不實作

## 8. SEO 與社群資訊

- Title：`立赫精密｜半導體設備維修與工程服務`
- Description：`立赫精密提供半導體設備維修、零組件更換與鋼瓶更換作業支援，重視安全規範、作業品質與完工紀錄。`

- 加入 favicon
- 使用語意化標籤：`header`、`nav`、`main`、`section`、`footer`
- 公司地址與電話確認後，再加入 Organization JSON-LD

## 9. 響應式與無障礙要求

- Breakpoints：手機、平板、桌機
- 360px 寬度不可產生橫向捲軸
- 主要內文字級至少 16px
- 文字與背景對比符合 WCAG AA
- 鍵盤可操作導覽列、選單及按鈕
- 所有互動元件具有明顯 focus 狀態
- 使用者放大文字至 200% 時仍可閱讀及操作
- 動畫不得影響閱讀，支援 reduced motion

## 10. 效能與品質門檻

- 首頁圖片使用 WebP／AVIF 並指定尺寸，避免版面位移
- Hero 圖控制容量，其餘圖片採 lazy loading
- 不載入不必要的 JavaScript 套件
- Lighthouse 目標：Performance、Accessibility、Best Practices、SEO 各 90 分以上
- 不在程式碼中放置 API Key、密碼或客戶機密資料
- GitHub Pages 部署後檢查所有圖片、錨點及子路徑

## 11. Antigravity 執行順序

1. 閱讀本規格及 `axequator-company-website.yaml`。
2. 檢查現有 Repository，保留既有 Git 歷史及使用者檔案。
3. 建立 Vite + React 專案並設定 `/company-product/` base path。
4. 先完成導覽列、Hero、服務項目及聯絡 CTA 的可辨識首頁。
5. 完成 About、Process、Safety、Contact 與 Footer。
6. 將所有待確認公司資料集中在一個內容資料檔，使用清楚 placeholder，不自行杜撰。
7. 完成響應式、無障礙、SEO 與效能處理。
8. 執行 lint、production build 及本機預覽。
9. 建立 GitHub Pages Actions workflow。
10. Push 至 GitHub，確認 Actions 成功及公開網址正常。
